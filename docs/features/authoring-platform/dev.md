# Authoring platform: for developers

What changed, where it lives, and how to extend it. The author-facing guide is
[docs/authoring.md](../../authoring.md); the plan and its test strategy are in
[plan.md](plan.md).

## The shape

```

            │                               │ createStage({...})       │ files
            ▼                               ▼                            ▼

  panels/panelStack.ts      tabs + one box per panel, remembers the open tab

  stage/chrome.ts           controls card + restart, readings card, caption, per chapter
  chapter.ts                createStage

```

## Decisions

- **The player owns the stack, keyed by the panel list.** Chapters with the same list share
  it (and its GL contexts and open tab); a different list disposes every runtime mounted on
  the old stack first, then rebuilds. A runtime instance serves one chapter and must be
  re-mountable after `dispose`.
- **Runtimes are cached per chapter for the page's life.** Leaving a chapter calls `exit`
  (pause), returning calls `enter` (resume) without `mount`. Coming back to the browser tab
  calls `resume`, never `enter`, so nothing is rebuilt. This fixed the 3D simulations
  restarting on tab return and issue zero freezing after the tab was hidden.
- **A chapter with nothing of its own shows its nearest neighbour's runtime** under the
  neighbour's id (`runtimeStepId`), instead of mounting the same runtime object twice.
- **Scenes are scoped per chapter.** `LerpettePanel.scope(target)` gives a chapter a private
  view of a panel that keeps a scene (only `viewport3d` today: own scene, camera, orbit
  controls, lights, on the panel's one renderer). `clear` empties it for a new run,
  `release` frees it. Panels that repaint from nothing every frame need no scope.
- **One clock.** The chapter runtime's rAF loop is the only one; `dt` is seconds clamped to
  1/30 s, and `ctx.time` accumulates `dt`, so it stops while the chapter is off screen.
  `World.advanceBy(dt)` takes it in fixed 1/120 s steps.
- **Stage chrome is per chapter and survives restart.** `stage:controls-collapsed`,
  `stage:readings`, `stage:pane` live in the owner's choices map; `reset(true)` (restart, a
  new build) keeps them, a first visit starts from the chapter's code.
- **Module and editor sources merge by name.** An editor build replaces the module's model
  and views name by name; configuration (`caption`, `panels`, `restart`, `wasm`) only comes
  from the module. Restart reruns the module, or rebuilds from the editor (a C++ instance
  keeps its statics, so rerunning the old instance would not be a clean start).
- **Validation happens at build, never throws.** content.ts reports every problem with an
  id from `lib/problems.ts`; a test keeps the catalogue, the reports and
  `docs/authoring/problems.md` (generated by `scripts/problems-doc.mjs`) in step.
- **Per-lesson libraries by include.** `scripts/build-wasm.sh` links `lerpettes/libs/<lib>`
  into a module only when the source includes one of its headers, and rebuilds the module
  when the library's archive is newer. Linking physics into every module was what put
  `Sphere`/`World` Embind names into lessons that never asked for them.
- **CSS lives beside its module**, imported by it: `libs/live-code/js/liveCode.css`,
  `framework/stage/chrome.css`, `framework/panels/{panelStack,textPanels}.css`. Every rule
  that targets those classes moved, `@media`/`@container` overrides included, so nothing
  left in `global.css` competes with them in the cascade. `styles.test.ts` checks that none
  came back, that each sheet is imported, and that media queries use only the breakpoints
  listed in `:root`.

## Extending

| To add | Do |
| --- | --- |
| a panel | a folder under `framework/panels/` with a `LerpettePanel`; one line in `registry.ts` `LOADERS` and `PANEL_LABELS`; its CSS beside it, imported by it. `panelRegistry.test.ts` checks the label. Give it `scope` if it holds a scene. |
| a reading kind | an entry in `KINDS` and a method on `Readings` (`readings/readings.ts`), styles in `stage/chrome.css`. |
| a language | an entry in `libs/live-code/js/languages.ts` (extension, build kind, editor mode, comment); the editor, the chapter runtime and the fence checks read it. |
| a `control.toml` key | one entry in `FIELDS` in `lib/control.ts` and a field on `LerpetteControl`. |
| an authoring problem | an id in `lib/problems.ts`, `report('<id>', …)` in content.ts, then `node scripts/problems-doc.mjs`. |
| a preset | a function returning `createChapterRuntime({...})` in `framework/runtimes/`. |

## Testing

- `npm test`: the C++ physics tests (now with `motion.h`), then vitest. New suites:
  `chapterRuntime`, `panelRegistry`, `theme`, `loadModule`, `languages`, `problems`,
  `content.platform`, `styles`, physics `helpers`, and the extended `control`, physics
  `world.*` tests.
- `node scripts/check-site.mjs`: the site walk, see `docs/testing/visual/README.md`.

## Known limits

- The stage chrome, the panel stack and the page chrome have no DOM unit tests (there is
  no DOM library in the repo); they are covered by `check-site`, which drives them in Chrome.
- Hand-written runtimes are still supported but no lesson uses one; such a runtime must
  call `ctx.stage.tick(now)` itself if it adds readings.
- `ctx.wasm` from a prebuilt module is shared by every run of a chapter (one instance per
  page), so a restart does not reset C++ statics in prebuilt modules.
- The C++ motion helpers (`integrate_euler`, `bounce_in_box`) are for lessons whose
  subject is something else; simple-body-dynamics keeps its explicit loops because they
  are what its prose teaches.
